# Export Old Registry Data - Implementation Summary

## Overview

This document describes the implementation of the data export functionality for migrating from the old application-based oracle registry to the new account-based registry (oracle-registry-v2).

## What Was Implemented

### 1. Migration Module (`src/migration.rs`)

A comprehensive Rust module that provides:

#### Data Structures

- **`ExportedVoter`**: Captures all voter data from old registry
  - Application ID, chain ID, account owner
  - Stake amounts (total and locked)
  - Registration and activity timestamps
  - Reputation data
  - Pending rewards

- **`ExportedReputation`**: Voter reputation metrics
  - Score, total votes, correct/incorrect votes
  - Correct streak tracking
  - Last updated timestamp

- **`ExportedMarket`**: Market/query data
  - Market ID, requester info
  - Question and outcomes
  - Timestamps (creation, deadline)
  - Fee paid and status
  - All votes and selected voters

- **`ExportedVote`**: Individual vote records
  - Voter identification (app ID and owner)
  - Outcome index and confidence
  - Timestamp and stake locked

- **`RegistryExport`**: Complete export container
  - Metadata (timestamp, version, counts)
  - All voters and active markets
  - Statistics and parameters

#### Functionality

- **`ExportBuilder`**: Fluent API for constructing exports
  ```rust
  let mut builder = ExportBuilder::new();
  builder.add_voter(voter);
  builder.set_metadata(metadata);
  builder.set_statistics(stats);
  builder.set_parameters(params);
  let export = builder.build()?;
  ```

- **Validation**: Comprehensive data validation
  - Voter count verification
  - Market count verification
  - Duplicate address detection
  - Stake consistency checks
  - Reputation consistency checks
  - Vote reference validation

- **Summary Generation**: Statistical summaries
  - Active/inactive voter counts
  - Markets with votes
  - Total stake and rewards
  - Average reputation

- **JSON Serialization**: Import/export to JSON
  ```rust
  let json = export.to_json()?;
  let loaded = RegistryExport::from_json(&json)?;
  ```

- **Voter Mapping**: App ID to account owner mapping
  ```rust
  let mapping = VoterMapping::from_export(&export);
  let owner = mapping.get_owner(&app_id);
  ```

#### Tests

Comprehensive unit tests covering:
- Export builder functionality
- Validation logic
- Summary generation
- JSON serialization/deserialization
- Voter mapping creation

### 2. Export Script (`scripts/export-old-registry-data.sh`)

A bash script that:

1. **Queries Old Registry**: Uses GraphQL to extract data
   - Voters with all metadata
   - Active markets with votes
   - Statistics and parameters

2. **Creates Export Files**:
   - `registry_export_TIMESTAMP.json` - Complete export
   - `voter_mapping_TIMESTAMP.json` - App ID to owner mapping
   - `export_summary_TIMESTAMP.txt` - Human-readable summary

3. **Validates Data**: Uses `jq` for JSON validation
   - Checks structure
   - Verifies counts
   - Generates statistics

4. **Provides Next Steps**: Clear guidance for migration

### 3. Test Script (`scripts/test-export-migration.sh`)

A test script that:
- Creates sample export data
- Validates JSON structure
- Tests voter mapping generation
- Generates summary reports
- Provides usage examples

### 4. Migration Guide (`oracle-registry-v2/MIGRATION_GUIDE.md`)

Comprehensive documentation covering:
- Migration overview and phases
- Step-by-step instructions
- Data mapping tables
- Troubleshooting guide
- Rollback plan
- Post-migration checklist

## Usage Examples

### Export Data from Old Registry

```bash
# Set registry configuration
export REGISTRY_CHAIN_ID="your_chain_id"
export REGISTRY_APP_ID="your_app_id"

# Run export
./scripts/export-old-registry-data.sh

# Review results
cat migration-data/export_summary_*.txt
```

### Validate Export in Rust

```rust
use oracle_registry_v2::migration::RegistryExport;

// Load and validate
let export = RegistryExport::from_json(&json_data)?;
let validation = export.validate();

if !validation.is_valid {
    for error in validation.errors {
        eprintln!("Error: {}", error);
    }
}

// Get summary
let summary = export.summary();
println!("Total voters: {}", summary.total_voters);
println!("Active voters: {}", summary.active_voters);
```

## Validation Checks

The export validation performs these checks:

1. **Metadata Validation**
   - Voter count matches actual voters
   - Market count matches actual markets

2. **Voter Validation**
   - No duplicate addresses
   - Locked stake ≤ total stake
   - Reputation votes are consistent
   - Inactive voters flagged if they have stake

3. **Market Validation**
   - Active markets have correct status
   - At least 2 outcomes per market
   - Votes reference valid voters

4. **Statistics Validation**
   - Total stake matches sum of voter stakes
   - Counts are consistent

## Performance Considerations

- Export is read-only (safe to run anytime)
- Large registries may take time to export
- JSON files can be large (100s of MB for many voters)
- Consider pagination for very large datasets
- Validation is fast (< 1 second for 1000s of voters)

## Security Considerations

- Export contains sensitive data (stakes, rewards)
- Store export files securely
- Don't commit export files to git
- Use secure channels for transfer
- Verify checksums after transfer
